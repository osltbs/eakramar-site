# eakramar-site

Статический сайт-визитка с полным CI/CD: сборка, сканирование и доставка
на боевой сервер через собственный пайплайн на self-hosted GitLab.

**Живой сайт:** https://eakramar.ru

---

## Что это показывает

Не «hello world из туториала», а рабочий конвейер на инфраструктуре,
поднятой с нуля:

- собственный образ сайта (nginx + статика) собирается из Dockerfile
- пайплайн **build → scan → deploy** на self-hosted GitLab
- прод тянет **проверенный** образ из приватного реестра — не пересобирает
- реестр доступен серверу только через **site-to-site VPN**, наружу не опубликован
- деплой по **хешу коммита** — воспроизводимость и откат на конкретную версию

## Конвейер

```
git push → GitLab CI
   ┌──────────┐   ┌──────────┐   ┌───────────┐
   │  build   │ → │   scan   │ → │  deploy   │
   └──────────┘   └──────────┘   └───────────┘
   образ в        trivy по        прод тянет
   реестр,        образу,         ТОТ ЖЕ образ
   тег = хеш      HIGH/CRITICAL   из реестра,
   + latest                       up -d
```

### build
Собирает образ, тегирует хешем коммита и `latest`, кладёт в GitLab Container
Registry. Флаг `--provenance=false` — иначе buildx добавляет attestation-манифесты,
несовместимые со встроенным реестром. Образ также сохраняется в tar-артефакт
для следующей стадии.

### scan
[Trivy](https://trivy.dev) сканирует образ на уязвимости HIGH и CRITICAL,
читая tar-артефакт из build — без обращения к реестру или Docker-сокету.
`--exit-code 1` + `allow_failure: true`: стадия честно падает при находках,
показывая проблему, но не блокирует деплой на текущем этапе.

### deploy
Раннер по SSH заходит на VPS, доставляет `compose.yaml`, логинится в реестр
(`--password-stdin`, токен не виден в списке процессов) и тянет образ:
`docker compose pull` + `up -d`. Образ приходит из реестра — тот самый,
что собрал build и проверил scan. Прод не пересобирает.

## Инфраструктура

Весь стек развёрнут самостоятельно:

```
Домашний стенд (Proxmox VE, вложенная виртуализация)
├── ВМ:  GitLab CE         — репозиторий, CI/CD, Container Registry
└── LXC: GitLab Runner     — executor docker, собирает образы

VPS (облако, белый IP)
└── nginx в Docker         — сайт eakramar.ru, TLS Let's Encrypt, systemd

Связь прод ↔ реестр — site-to-site OpenVPN:
  VPS сайта → VPS-шлюз → домашний MikroTik → приватный реестр GitLab
```

Реестр в домашней сети недоступен из интернета. Чтобы прод мог тянуть образы,
он входит в VPN как клиент — три OpenVPN-инстанса (шлюз на VPS, домашний
MikroTik и VPS сайта), с tls-crypt для обхода DPI на мобильном канале.

## Стек

- **Docker / Compose** — сборка и запуск
- **GitLab CE** — репозиторий, CI/CD, Container Registry
- **GitLab Runner** — executor docker в LXC
- **Trivy** — сканирование уязвимостей
- **nginx** — веб-сервер, TLS
- **Proxmox VE** — виртуализация
- **OpenVPN** — site-to-site доступ к приватному реестру

## Безопасность

- адреса, токены и ключи — в защищённых CI-переменных, в коде только `$ПЕРЕМЕННЫЕ`
- приватный ключ деплоя передаётся через base64 (многострочный секрет в переменной)
- логин в реестр через `--password-stdin` — токен не попадает в `ps`
- базовые образы зафиксированы по версии (`docker:27-cli`, `alpine:3.20`, `trivy:0.58.0`)
- реестр не опубликован в интернет — доступен проду только по VPN
- trivy проверяет образ на уязвимости перед выкаткой

---

## Версионирование и откат

- **main** — продакшн, деплоится; feature-ветки проверяются CI, но не деплоятся
- образы всех сборок хранятся в реестре с тегом по хешу коммита
- **откат срочный** — на проде `TAG=<хеш> docker compose up -d` (запуск старого образа)
- **откат постоянный** — `git revert` в main, пайплайн выкатывает откат
- релизы помечаются тегами `vX.Y.Z` (семантические версии)

## Решённые задачи

Проект собран через реальные инженерные проблемы, а не по готовому рецепту:

- **Docker в LXC на Proxmox** — вложенная виртуализация потребовала nesting,
  доступа к cgroups и обхода AppArmor на уровне конфига контейнера
- **Формат образа для реестра** — buildx по умолчанию создаёт attestation-манифесты,
  несовместимые со встроенным реестром; отключено `--provenance=false`
- **Trivy без сокета** — сканирование tar-артефакта вместо обращения к Docker
  или приватному реестру (trivy блокирует приватные IP по SSRF-защите)
- **SSH-ключ в CI** — многострочный ключ ломался в переменной; решено base64
- **Приватный реестр из облака** — прод достаёт домашний реестр через
  site-to-site VPN; обход DPI мобильного оператора через tls-crypt на порту 443
- **Честный build→scan→deploy** — прод тянет проверенный образ из реестра,
  не пересобирает: один образ от сборки до прода
